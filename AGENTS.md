# Local Knowledge Terminal contributor guide

## Product boundaries

- Keep corpus ingestion, retrieval, model inference, card composition, and
  output rendering in separate modules.
- The browser GUI is the first output adapter. E-ink and audio must consume the
  same card JSON contract and must not be imported by the core service.
- Book files, generated indexes, model weights, runtime builds, secrets, and
  rendered artifacts never belong in Git.
- Citations are derived from retrieved corpus records, not generated by the
  language model.

## Validation

Run before every commit:

```bash
python -m unittest discover -s tests -v
python -m compileall -q lkt tests
```

For Pi changes, also verify `/api/health`, generate a card from a real book
entry, and record the model/runtime revisions in the handoff.

## Git workflow

Use focused, imperative commits. Push completed work to the configured remote.
Do not rewrite or discard unrelated user changes.
